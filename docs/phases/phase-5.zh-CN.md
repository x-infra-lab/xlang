# 阶段 5 — XOS 虚拟内存

**当前阶段：** P5。

P5 在 P4 CPU 与物理 RAM 之间插入操作系统层。寄存器保存的地址现在都是虚拟
地址：取指、load、store、栈访问和 syscall 缓冲区统一经过同一张页表。

## 地址空间布局

| 虚拟地址范围 | 用途 | 初始权限 |
|--------------|------|----------|
| `0x00000000...` | 已加载程序 | `r-x` |
| `0x00010000...` | `brk` 堆 | 初始未映射，增长后为 `rw-` |
| `0x00040000...` | 匿名 `mmap` 区域 | 调用方指定 |
| `0x000ffc00–0x000fffff` | 四页栈 | `rw-` |

页大小为 256 字节，因此调试器可以一次展示多条翻译关系，而不会产生巨量输出。
物理页框独立于虚拟页号分配，确保能真实观察地址翻译，而不是退化为恒等映射。

## 页表与权限

每条映射记录虚拟页、物理页框、`rwx` 位和可读的区域名称。同一个翻译器负责：

- 取指时检查执行权限；
- load 与 syscall 输入检查读权限；
- store 与栈压入检查写权限；
- 逐字节处理跨页访问。

未映射或权限不允许的访问会抛出 `PageFault`，其中包含故障指令、虚拟地址、
访问类型、映射名称和权限。未知 opcode 等 P4 fault 仍保持独立且确定。

## 堆与匿名映射

`XOS.brk(0)` 查询当前 break；增长时分配足够的 `rw-` 页，缩小时释放完整页及
物理页框。`XOS.mmap` 自动选择页对齐地址、向上取整长度并应用调用方权限。
`mprotect` 可修改已映射页权限，供测试和后续 loader 使用。

```bash
./gradlew :xlang-cli:run --args="mem show"
./gradlew :xlang-cli:run --args="mem map 512 r--"
```

可视化输出包含合并后的虚拟区间、权限位、物理页框号、当前 break 和物理页使用量。

## 第一个 syscall

Opcode `70` 使用以下寄存器 ABI 调用 `syscall`：

| 寄存器 | 含义 |
|--------|------|
| `r0` | syscall 编号（`1` 为 `write`）及返回值 |
| `r1` | 文件描述符（`1` stdout、`2` stderr） |
| `r2` | 虚拟缓冲区地址 |
| `r3` | 字节长度 |

`write` 通过页表权限读取 guest 缓冲区，把字节追加到可观察的机器输出，并在 `r0`
中返回写入字节数。CLI 会在最终寄存器状态之前打印这段输出。

## 验证

```bash
./gradlew build
./gradlew phaseInfo
```

测试覆盖启动映射、执行/读/写权限、未映射缺页、跨页 64 位值、堆增长与收缩、
mmap/mprotect、页框耗尽、write 输出与返回值、非法 syscall、映射可视化，以及
地址翻译下的全部 P4 机器行为。
