# 阶段 4 — XMachine 与 XCPU

**当前阶段：** P4。

P4 启动 xlang 的第一台模拟计算机。它暂时还不能运行编译后的 xlang 源码——这座
桥会在 P6 接上——但已经能从 RAM 中逐条取指、解码并执行真正编码的指令。

## 机器模型

- 默认 64 KiB 字节寻址 RAM，Java API 可配置容量。
- 8 个 64 位寄存器 `r0`–`r7`；`r7` 是向低地址增长的栈指针。
- 字节寻址程序计数器，以及零标志 `Z` 和负标志 `N`。
- 32 位跳转目标、64 位立即数与内存值，均采用小端序。
- 栈从 RAM 末端开始；`call` 压入返回地址，`ret` 使用和 `push` / `pop`
  相同、可观察的栈机制弹出地址。
- 算术按 64 位自然回绕，`cmp` 使用有符号 64 位顺序。

## P4 指令编码

| Opcode | opcode 后的编码 | 含义 |
|-------:|-----------------|------|
| `00` | — | `halt` |
| `01` | — | `nop` |
| `10` | `dst:u8 imm:i64` | `movi` |
| `11` | `dst:u8 src:u8` | `mov` |
| `20`–`24` | `dst:u8 lhs:u8 rhs:u8` | `add`、`sub`、`mul`、`div`、`mod` |
| `30` | `lhs:u8 rhs:u8` | 有符号 `cmp` 并设置标志 |
| `31`–`34` | `target:i32` | `jmp`、`jz`、`jnz`、`jn` |
| `40`–`41` | `value-reg:u8 address-reg:u8` | `load64`、`store64` |
| `50`–`51` | `reg:u8` | `push`、`pop` |
| `60` | `target:i32` | `call` |
| `61` | — | `ret` |

寄存器编码为 `00`–`07`，多字节字段采用小端序。

## 运行手写机器码

下面的程序把十进制 42 装入 `r0`，然后停机：

```text
10 00 2a 00 00 00 00 00 00 00 00
│  │  └────────── i64 42 ─────────┘
│  └─ r0
└─ movi                         halt ┘
```

```bash
./gradlew :xlang-cli:run --args="run '10 00 2a 00 00 00 00 00 00 00 00'"
./gradlew :xlang-cli:run --args="trace '10 00 2a 00 00 00 00 00 00 00 00'"
```

`run` 打印停机后的全部寄存器和标志；`trace` 还会逐条打印指令地址、编码字节、
反汇编、下一条 PC、`r0` 和执行后的标志。

## Fault 与安全护栏

遇到未知 opcode、截断指令、非法寄存器、除零/模零、RAM 越界、非法跳转或返回
地址、栈下溢和指令步数耗尽时，机器会携带故障指令地址进行 trap。默认的一百万
步上限使 CLI 可以安全运行意外的死循环。
